# personal-context-init

听完邵艾伦和孙宇晨的访谈，我也想试试「一切 AI 化」：从身体管理、学习到工作和日常决策，看看 AI 能在多大程度上参与自己的生活。

这些事情有一个共同的起点：AI 得先了解我。我的身体状况、工作背景、时间安排、偏好，以及最近想做成什么，都会影响它给出的建议。而这些信息还会不断变化，每次聊天都从头介绍一遍，实在有点麻烦。

所以我做了 **personal-context-init**，作为这次尝试的第一步：先建立一份 AI 能读取、也能持续帮我维护的个人档案。选一个本地文件夹，让这个 Skill 初始化好记录规则，以后就可以通过聊天逐步补充资料，再让 AI 结合这些信息帮你做计划、分析问题。保存前，它会说明准备改什么，等你确认后再写入。

访谈里提到的薄肌，就是一个很好的场景。把身体数据、训练基础和可投入的时间记录下来，就可以让 AI 据此安排训练：

> 我的身高、体重和体脂率分别是……，每周能训练三次，目标是练出薄肌。帮我记录这些情况，再结合我的训练基础，制定一个月的训练计划，列出动作、组数和每周安排。

学习也一样，让计划从自己的基础和时间出发：

> 我想在半年后用英语做工作汇报，每周能投入五个小时。结合我目前的英语水平，帮我安排学习计划。

工作和生活有了变化，也可以放在一起考虑：

> 我刚换了工作，接下来三个月要优先熟悉新业务。结合我已有的学习和训练安排，帮我看看哪些目标需要调整。

从一件具体的事开始，把有用的信息留下来，再逐步扩展到更多方面。随着档案积累，AI 就能参考你的实际情况，也能看到不同目标之间的联系。

资料以 **Markdown 和 JSON** 保存在你自己的文件夹里，可以直接查看和编辑，也可以用 Obsidian 阅读。换一个助手时，只要它能访问这个文件夹、读取其中的规则，就能继续使用这份档案。

## 怎么用

### 1. 安装 Skill

将本项目中的 `skills/personal-context-init/` 整个文件夹放入所用 AI 工具支持的技能目录，保留其中的模板、说明和辅助脚本。具体安装位置和刷新方式由该工具决定。

助手需要能够读取、写入本地文件并执行辅助脚本。当前初始化实现需要 Python 3.9+ 和系统 IANA 时区数据，仅使用 Python 标准库；用户不需要手动执行脚本。

暂不安装也可以让具备这些能力的助手直接读取 [SKILL.md](skills/personal-context-init/SKILL.md)。

### 2. 指定目录，让 AI 初始化

在助手中说：

> 请调用 personal-context-init，在 `/你的路径/my-context` 初始化个人信息档案，使用中文和 Asia/Shanghai 时区。先展示文件安排和变更方案，等我确认后完成初始化。

AI 会检查目录，展示准备创建或修改的文件，等你确认后完成初始化和校验。这些步骤由 AI 调用辅助脚本完成，你不用手动运行命令。请为个人档案单独选一个文件夹，与本项目分开存放。

### 3. 后续直接聊天

在能访问这个文件夹的助手中继续使用：

> 帮我记下今天提供的新情况。

> 我之前的目标变了，请帮我更新。

> 根据已有资料分析这个问题，本次只查询，不保存。

初始化 Skill 到这里就完成了它的主要工作。日常记录、查询和纠错，由 AI 按档案中的规则处理，无需再次调用 Skill。

每次新聊天时，记得让助手能访问这份档案。如果它没有自动加载规则，可以先说：「请读取这个目录的 `AGENTS.md`，再结合已有资料回答。」

## 初始化后，文件夹里有什么

```text
my-context/
├── AGENTS.md             # AI 读取入口与关键约束
├── CLAUDE.md             # 仅一行 @AGENTS.md
├── POLICY.md             # 完整的通用维护规范
├── README.md             # 使用说明与实际文件目录
├── .gitignore            # 忽略 Obsidian 配置和临时文件
└── .personal-context.json # 规范版本与升级基线
```

主题目录随实际记录按需建立：

| 目录         | 保存什么                                   |
| ------------ | ------------------------------------------ |
| `stable/`  | 较稳定的背景与约束，或结构化数据的主题说明 |
| `mutable/` | 当前状态、近期偏好和临时意图               |
| `history/` | 需要积累的事件与纠错记录，使用 JSON        |

不会预建一堆空主题，也不会填入示例个人事实。初始化 Skill 可以停用，项目中的规则和资料仍然可用。

## 记录遵循什么规则

- **忠实记录。** 只保存你明确提供、确认或授权导入的信息，不猜测未知事实，建议与事实分开。
- **写入前说明。** AI 先说明要修改哪些内容，经你确认后保存；聊天讨论不自动写入。
- **区分时间。** 发生日期、录入时间和文件更新时间分开，不把今天录入的信息当作今天发生。
- **规则集中。** AGENTS.md 提供入口，POLICY.md 保存通用规范，具体字段与单位由主题说明定义。
- **格式通用。** 使用普通 Markdown 链接，不依赖 Obsidian 双链或专有嵌入；公式使用 `$...$` 和 `$$...$$`。

Markdown 可以包含 front matter 元数据，结构化个人记录使用 JSON。本项目自身的 Python 脚本和工具配置不属于个人资料。

## 已经有资料目录怎么办

同样调用这个 Skill，并明确指定已有目录：

> 请将 `/我的已有目录` 接入 personal-context-init。先阅读现有规则，保留已有资料，展示接入方案，等我确认后执行。

AI 会保留现有资料和目录结构。已有 AGENTS.md、README.md、.gitignore 会审阅后合并；遇到已有 POLICY.md 或包含独有规则的 CLAUDE.md，会先提出冲突解决方案，不直接覆盖。

已有 JSONL 仅报告并保留，转换成 JSON 需要单独的迁移方案。重复初始化同一版本、且配置和文件均未变化时，不重写文件或刷新时间戳。

详见 [已有目录接入规则](skills/personal-context-init/references/existing-directory.md)。

## 以后如何升级规范

日常使用无需升级。以后你希望采用新规则时，取得新版 Skill，再告诉 AI：

> 请检查这个档案的规范版本，比较新版规则和我的定制，先展示升级差异，等我确认后应用。

升级会比较旧模板、当前文件和新模板：保留用户定制，冲突先确认，检查通过后才更新版本信息。普通规范升级不修改个人事实，也不自动迁移数据格式。

当前随附中文模板 `1.0.0`。详见 [规范升级规则](skills/personal-context-init/references/upgrades.md)。

## Obsidian 与同步

Obsidian 仅是可选阅读界面，不需要安装插件才能使用这份档案。初始化不会创建 `.obsidian/`，生成的 `.gitignore` 会忽略它。

可以用 Git 保留文件版本，并按需通过 GitHub 同步；这与 `history/` 中的事件记录是两回事。初始化不自动提交、推送或公开资料，项目代码与个人资料应分别保存。

## 开发与验证

辅助脚本是 Skill 内部的实现工具，用于生成变更计划、校验文件和处理规范升级。**普通用户无需学习它们的参数，也无需在日常聊天时运行它们。** 命令细节见 [SKILL.md](skills/personal-context-init/SKILL.md)。

在项目根目录运行测试：

```sh
python3 -m unittest discover -s tests -v
```

测试覆盖空目录初始化、已有目录接入、重复运行、模拟新版升级，以及冲突处理、过期计划拦截和异常回滚。结构校验不代表事实正确或 AI 一定遵守规则；自定义规则含义仍需审阅。
