# 接入已有目录

先确认目录归属与读取适用指令。只检查任务相关资料，不把个人内容放入工具查询、公开模板或测试样例。

- 已有 AGENTS.md：助手读懂原有规则后，可在末尾增加管理块。既有文字原样保留；检查是否与新增入口冲突。
- 已有 README.md：追加入口块，保留正文与文件清单。不要把所有未分类文件自动登记成个人事实。发现未登记资料，列出并让用户决定是否纳入。
- 已有 POLICY.md：只要不是本框架管理块，自动接入就阻塞。先比较规则，准备完整合并稿。模板默认规则不能覆盖用户现有约束。
- 已有 CLAUDE.md：若不止 `@AGENTS.md`，阻塞。先将独有规则迁移到用户选择的 AGENTS 或 POLICY 位置，再将 CLAUDE 缩成单行；这几个修改必须在同一审阅方案中。
- 已有 .gitignore：只追加管理块，保留原规则。忽略 `.obsidian/` 不会自动解除已跟踪文件；如果发现已跟踪配置，说明情况，单独授权后才调整 Git 索引。
- 已有未被本框架识别的管理标记、损坏清单或不支持的清单版本：停止自动写入，报告实际问题。
- 已有 JSONL：仅报告；格式迁移需独立许可与方案，保持 ID、字段、纠错引用及发生时间。初始化脚本不会读取并改写这些记录。

## 审阅冲突解决稿

把完整文件内容放进目标目录外的 JSON 对象，键只允许 `AGENTS.md`、`CLAUDE.md`、`POLICY.md`、`README.md`、`.gitignore`。保留原有内容与管理块界限。对 POLICY 可将模板管理块作为基底，将用户规则合并进入该块，或把明确优先的用户例外放在块外；必须消除实际冲突，不能靠“已合并”宣称完成。

重新运行 plan 并提供 `--resolutions`，检查新差异，再取得对该最终方案的许可。计划文件可能包含已有规则的完整内容，只放临时目录，不提交或发布。完成后可删除此次明确创建的临时计划，不删除用户文件。

同版本重复初始化不会覆盖定制，也不会为没有变化的文件更新时间。已存在有效清单但缺文件时，优先用检查结果确定修复范围；补齐标准文件后保留其他数据。不存在版本清单的旧项目一律按已有目录接入，不猜其历史版本。
