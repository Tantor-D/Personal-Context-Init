# 个人信息维护规范

## 真实性与写入

只保存用户明确提供、确认或授权导入的事实。未知字段省略，未知正文留空，不用零值或猜测填充。建议、推断和复盘结论明确标注性质，不覆盖原始事实。

个人数据的新增、导入、修改与删除，先说明理解、文件范围、字段、时间安排及目录更新；用户明确许可方案后才写入。仅讨论不授权保存。新主题存储方式不明确时先提出方案。

## 文件职责

- AGENTS.md 保存入口与关键协作要求；CLAUDE.md 仅含 `@AGENTS.md`。
- README.md 登记实际文件，使用相对链接；新增、移动、重命名、删除文件时同步维护目录和相关引用。
- POLICY.md 保存通用规则。主题字段、单位、可选项和读取方式放在主题说明，不重复维护。
- stable/ 的主题选择“正文直接保存”或“说明与 JSON 数据分离”。分离型主题必须明确链接 history/ 的实际数据，查询当前值同样要读取数据。
- mutable/ 保存自身全部当前内容，不依赖 history/ 补齐，不将旧内容归档到 history/。
- history/ 是事件数据层，不是所有文件的旧版归档目录。主题按需建立，不预建空主题、示例个人事实、影子档案或摘要副本。

## 格式与时间

个人资料只使用 Markdown 和 JSON，不新增 JSONL。档案 Markdown 从第一行写 YAML front matter，包含带引号、含时区、精确到秒的 updated_at。CLAUDE.md 与 .gitignore 按工具格式处理，无需 front matter。

JSON 根对象先写 _meta，再写 data；_meta 包含 updated_at，data 的对象或数组结构由主题说明定义。禁止注释、尾随逗号与重复键。管理清单 .personal-context.json 也采用 _meta 与 data。

采用初始化配置中的时区，维护时间必须来自实际时钟。updated_at 是实际修改时间；recorded_at 是录入时间；occurred_on 是发生日期，默认 YYYY-MM-DD。不把录入日期当发生日期，不补造来源没有的时间。来源含更精确时间时，说明是否保留。只有实际修改才更新时间；手工编辑漏更新时不伪造旧编辑时刻。

## 通用阅读格式

Obsidian 仅是可选阅读界面。引用使用标准 Markdown 链接和相对文件路径，图片使用标准 Markdown 图片语法。禁止 Obsidian 双链、笔记嵌入、专有块标识引用和 obsidian:// 链接。

行内公式用 `$...$`，独立公式用各占一行的 `$$` 包围；不用 `\(...\)` 或 `\[...\]`。公式渲染依赖阅读器的数学扩展，但不要求 Obsidian。

## 当前状态与有效期

覆盖更新时保留其他有效内容，移除被明确替代的内容，不自行推断已完成。较稳定信息也可能变化。临时偏好不永久覆盖客观事实和常态约束。

偏好可使用 expires_on；null 表示持续有效，日期表示有效至配置时区当天结束。过期偏好不应用，不因读取就删除。文件更新时间不代表每项事实都新鲜。

## 事件、纠错与读取

结构化事件包含唯一固定 id、occurred_on、recorded_at、非空 source 与 data 或 values；note 可选。主题说明定义载荷、单位和同日多次记录的区分方式。

新事件追加记录，不覆盖旧事件。纠错追加完整替代记录，replaces 指向当前有效记录；未变字段也保留。不产生循环、悬空引用或多个替代分支，不复用 ID。被替代记录仅供追溯，不参与当前值或趋势计算。发生日期只有确实有误时才纠正。

读取按实际发生日期和明确提供的精度排序，不按数组位置、录入时间或文件修改时间推断事件先后。同日无法判断先后就并列说明。重复请求先核对，不因数值相同就将不同日期的事件去重。

历史内容不自动成为当前偏好。明确授权删除时按指定范围处理，并检查引用完整性，不以追加原则拒绝删除。

## 校验与版本

更新后检查文件目录和链接、Markdown 元数据、JSON 语法、字段与单位、ID 和纠错关系。说明检查范围，不声称完成未做的检查。

“不保留历史”指不额外创建旧版文件或将其迁入 history/。Git 可以保留包括 mutable/ 在内的全部版本，GitHub 同步可选。Git 文件版本与 history/ 事件记录不互相替代。当前查询遵循当前文件及有效事件，不自动使用 Git 旧内容。

允许版本留存不代表已配置自动提交、同步或公开发布。当前内容删除不代表清除了 Git 历史、远程副本或第三方备份。
